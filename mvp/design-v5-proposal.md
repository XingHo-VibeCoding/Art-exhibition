## 2. 展示系统：三层结构

### 2.1 恒定层 · 展陈骨架（不随作品变）

| 项 | 规格 | 来源 |
|---|---|---|
| 基本单元 | 统一外框 **2:3** 竖版 | 沿用 AC-26 |
| 装裱方式 | 作品按**原比例完整放入**，四周留卡纸（mat），**零裁切** | `mvp/fate-card` 已验证的手法 |
| 卡纸宽度 | 外框短边的 **6%**（可调，作为视觉呼吸的常量） | 新增 |
| 铭牌位置 | 卡纸下沿居中，三级字号（作品名 > 系列 > 编号） | 沿用 AC-74 |
| 列数 | 4 / 3 / 2 列（≥1280 / 768–1279 / <768） | 沿用 AC-27 |
| 卡片间距 | `(可用宽 − 卡片宽之和) ÷ (列数 + 1)`，**≥ 卡片宽 5%** | 沿用 AC-72 |
| 页面留白 | 左右各 8%（桌面）/ 6%（手机） | 沿用 AC-73 |
| 视觉重心 | 落在**中线带**（中部偏上） | 沿用 §6.2 |

**这一层永远不动。** 它负责让 74 张风格各异的作品，被同一套规矩郑重对待——这正是美术馆的做法：不要求展品同风格，只要求展陈系统统一。

### 2.2 变量层 · 环境色随作品（每张一套）

**机制**（三步，只在聚焦视图触发，不在网格里跑 74 次）：

1. **取色**：把当前作品降采样到 32×32，算两个值 —— 明度中位数 `L`、色相直方图峰值 `H`
2. **受控生成**（关键：不是直接用原图颜色）：
   - 明度：根据 `L` 落到两个窄带之一 —— 深带 `[0.18, 0.32]` 或 浅带 `[0.82, 0.92]`
   - 饱和度：压到 `S ≤ 0.15`（墙不抢画）
   - 色相：取自 `H`
3. **广播**：写入 CSS 变量 `--wall` / `--mat` / `--ink`，背景、卡纸、阴影全部由它派生

**兜底**：取色失败（大图超时 / 跨域）→ 回退到统一的中性灰白，不报错、不留白。

**★ 附带解决的老债**：因为明度被锁在窄带内，**AC-46「两块大面积色域明度反差 ≤3:1」与六套主题的冲突自动消失**——不再需要为每套主题单独调明度。

### 2.3 语法层 · 「对位」（语法恒定，方言可变）

**核心手法**：把「对位」从印刷里**抽出来当语法**，印刷降级为其中一种方言。

> 「对位」= 从"没对上"到"对上"。这是所有材质的**共同物理动作**：版与纸对上、焦距对上、纸片落在位置上。

| 作品材质标签 | 「对位」的方言 | 未对上时的状态 |
|---|---|---|
| `print` 印刷 | 错版合拢 | 色版错开 2–4px |
| `film` 胶片 | 齿孔推进一格 | 画面偏出片窗 |
| `photo` 摄影 | 焦点由虚到实 | 轻微失焦 |
| `collage` 拼贴 | 纸片落定 | 纸片浮起待落 |
| `digital` 数字插画 | 墨色显影 | 墨量由稀到密 |

**节拍骨架沿用 §6.5，不重新发明**：

| 段 | 占比 | 曲线 |
|---|---|---|
| 走位 | 60% | 匀速（刮墨 / 推进） |
| 收束 | 30% | 慢起快走（揭纸） |
| **高光** | **10%** | 快起急停，**只此一次，之后无残余动作** |

**作品表新增字段**：

```
material: print | film | photo | collage | digital | gameui
```

这一个字段，就是连接「恒定容器」与「可变作品」的桥。

## 3. 作者反馈系统（后端）

### 3.1 设计定位（先说清楚，它决定后面所有选择）

PRD §4.2 A3 把「用户系统 / 评论 / 社交」列为**永久不做**，理由是「展馆不需要留言簿才能看画」。

**这个理由今天仍然成立——观众依然不需要它。** 但本次需求是**作者侧**的：「让我知道哪张被喜欢」。
两个问题不同，导出不同设计：

- ❌ **不做**点赞排行榜、热门推荐、社交分享 —— 会把观众的眼睛从作品引到数字上
- ✅ **做**「安静的热度」：不显示数字，只在作者视图可见

### 3.2 功能清单

| 级别 | 功能 | 观众看到什么 | 门槛 |
|---|---|---|---|
| L1 | 点赞 | 一颗心，点亮 / 再点熄灭 | 零门槛，匿名 |
| L2 | 一句话感想 | 昵称（可留空）+ ≤50 字，按时间倒序列在该作品下方 | 零门槛 |
| — | 作者视图 | 每张作品的点赞数 + 感想清单 | 仅作者（本地密钥或私密路径） |

### 3.3 数据模型（三张表）

```
works     (id, series, seq, title, material)
          -- 静态作品表，本地维护，可随前端一起部署

likes     (id, work_id, visitor_id, created_at)
          -- 唯一索引 (work_id, visitor_id)：一人一作品一票

notes     (id, work_id, visitor_id, nickname, body, status, created_at)
          -- status: visible | hidden（作者可隐藏，不删除）
```

### 3.4 接口（4 个端点）

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/like` | `{workId, visitorId}` → `{liked, count}` |
| `GET` | `/api/stats` | 返回全部作品的点赞数与感想数（供排序用） |
| `POST` | `/api/note` | `{workId, visitorId, nickname, body}` → `{ok}` |
| `GET` | `/api/notes?workId=` | 取某作品的可见感想列表 |

**安全要求**（不写死会被刷）：

- `body` 长度服务端强校验 ≤ 50 字
- 同 `visitorId` 对同一 `workId`：点赞 1 次、感想 1 条
- 基础频率限制：同 IP 每分钟 ≤ 10 次写操作

### 3.5 ★ 排序策略（D4 的落地，这一条最需要克制）

D4 选了「不显示数字但影响排序」。**风险**：动态排序会破坏"被策展过"的秩序——美术馆不按参观人数重排画。

给出两个方案，请作者选：

**方案 甲（保守）· 位次不动，热度决定入场先后**
作品的**位置**永远按作者的策展顺序（`works.seq`）。热度只影响 §6.5 里那个「错峰入位」的**时间差**：被喜欢的先入场。
→ 观众**说不出来哪里不一样**，只觉得"这面墙有生气"。秩序零损失。

**方案 乙（进取）· 热度微调位次**
同系列内，热度前 20% 的作品**最多提前一位**（不多于一位）。位次会长，但幅度受限。
→ 更直接地体现"受欢迎"，代价是作者排的策展顺序会被轻微改写。

**推荐甲。** 理由：它把"热度"翻译成了**节奏**而不是**等级**——这恰好是 §6.5 那套「时间轴 60-30-10」的延长线，不用新增机制。

## 4. 技术选型

### 4.1 硬约束

| # | 约束 | 来源 |
|---|---|---|
| C1 | 观众**零门槛**：不要求任何账号 | D3 |
| C2 | 免费，尽量不需要信用卡 | 项目性质 |
| C3 | 数据归作者自己 | 作品站定位 |
| C4 | 站点已部署在 **GitHub Pages**（纯静态，不能跑服务端代码） | 现状 |
| C5 | 互动层失败**不能影响浏览** | v4 的 AC-38 精神 |

### 4.2 候选对比

| 方案 | 匿名可赞 | 观众门槛 | 免费 | 年成本 | 备注 |
|---|---|---|---|---|---|
| **A. Cloudflare Workers + D1** | ✅ | 无 | ✅ 无需信用卡 | 0 | Workers 10 万请求/天、D1 5GB，够用几千倍 |
| B. Supabase | ✅ | 无 | ✅ | 0 | 前端直连，需写 RLS 规则 |
| C. Giscus（GitHub Discussions） | ✅ | **须有 GitHub 账号** | ✅ | 0 | 违反 C1，**出局** |
| D. WorkBuddy 云服务 | ✅ | 无 | ✅ | 0 | 本机现成；平台绑定 |
| E. Disqus 等 SaaS | ✅ | 无 | 带广告 | 0 | 数据在第三方，违反 C3 |

**倾向 A**：一个 Worker 就能提供 §3.4 的全部四个端点，D1 存三张表，免费额度对个人作品站是压倒性富余。

### 4.3 ⚠️ 一个必须提前知道的风险

**国内可访问性。** 站点现在在 `github.io`，后端若选 `*.workers.dev`，这两个域名在中国大陆都可能不稳定。

- 如果观众主要是**国内的朋友、同学**→ 建议后端选国内平台（腾讯云开发 / 阿里云函数计算），前端也一并迁到国内静态托管
- 如果观众是**泛互联网人群**→ CF Workers 没问题

**这条不影响方案设计，但影响选型。** 需要作者先回答一句：**你希望谁打开这个站？**
